## 一、业务背景

### 1.1 现状问题

| 问题 | 说明 |
|------|------|
| 优惠券功能缺失 | 平台目前没有完整的优惠券体系 |
| 运营效率低 | 做活动只能通过开发发版，响应速度慢 |
| 获客成本高 | 新客转化难，首单转化率低 |
| 客单价低 | 客户单次采购金额偏小 |

### 1.2 目标

| 目标 | 说明 |
|------|------|
| 新客转化 | 提升新用户首次下单转化率 |
| 客单价提升 | 平均订单金额提升 |
| 运营效率 | 配置即上线，无需发版 |

## 八、退款退券规则

| 场景 | 处理 |
|------|------|
| 优惠券已使用 | ❌ 不退回 |
| 优惠券未使用+未过期 | ✅ 退回至客户账户，可继续使用（有效期不变） |
| 优惠券未使用+已过期 | ❌ 失效作废，不可再用 |

### 8.1 多商品优惠分摊原则

**通用原则**：按各商品金额占订单商品总金额的比例计算分摊

```
商品A分摊优惠 = 优惠券总优惠 × (商品A金额 / 订单商品总金额)
```

#### 满减券多商品分摊示例

| 字段 | 值 |
|------|------|
| 优惠券 | 满500减50 |
| 商品A | 600元 |
| 商品B | 400元 |
| 订单商品总金额 | 1000元 |

| 商品 | 金额 | 占比 | 分摊优惠 | 实付金额 |
|------|------|------|---------|---------|
| 商品A | 600元 | 60% | -30元 | 570元 |
| 商品B | 400元 | 40% | -20元 | 380元 |
| **合计** | 1000元 | 100% | -50元 | 950元 |

#### 折扣券多商品分摊示例

| 字段 | 值 |
|------|------|
| 优惠券 | 满300享8折 |
| 商品A | 600元 |
| 商品B | 400元 |
| 订单商品总金额 | 1000元 |
| 折扣率 | 0.8 |
| 优惠金额 | 200元 |

| 商品 | 金额 | 占比 | 分摊优惠 | 实付金额 |
|------|------|------|---------|---------|
| 商品A | 600元 | 60% | -120元 | 480元 |
| 商品B | 400元 | 40% | -80元 | 320元 |
| **合计** | 1000元 | 100% | -200元 | 800元 |

### 8.2 多商品退款规则

#### 8.2.1 整单退款（全部商品退款）

| 场景 | 处理 |
|------|------|
| 优惠券未使用 | ✅ 退回账户（有效期不变），恢复可用状态 |
| 优惠券已使用 | ❌ 已使用，不退回 |

#### 8.2.2 部分退款（部分商品退款）

**核心原则**：
1. 按退款商品金额占比计算应退金额（含优惠分摊部分）
2. **已优惠部分不追溯退还**
3. 剩余商品继续使用原优惠券，优惠保持不变

**计算公式**：
```
退款商品应退金额 = 退款商品实付金额（含优惠分摊）
优惠不退还金额 = 退款商品分摊的优惠金额
剩余商品优惠 = 原优惠 - 退款商品分摊优惠（保持不变）
```

**满减券部分退款示例**：

| 字段 | 值 |
|------|------|
| 优惠券 | 满500减50 |
| 商品A | 600元（分摊优惠30元，实付570元） |
| 商品B | 400元（分摊优惠20元，实付380元） |
| 订单实付 | 950元 |

| 场景 | 操作 | 结果 |
|------|------|------|
| 整单退款 | 退款商品A+商品B | 优惠券已使用，不退回 |
| 部分退款（商品A） | 退款商品A，保留商品B | 退款570元，优惠券不追溯退还，商品B保持原优惠 |

**注意事项**：
- 部分退款后，剩余订单即使金额低于门槛，原优惠券仍然有效（订单已使用，不可更换）
- 每单限用1张优惠券，部分退款不影响优惠券使用状态

### 8.3 退款优惠券状态变化（v1.5新增）

#### 8.3.1 整单退款场景

| 场景 | 优惠券状态 | 退回可用数量 | 说明 |
|------|-----------|-------------|------|
| 整单退款+优惠券未使用+未过期 | 退回账户 | 1张 | 有效期不变 |
| 整单退款+优惠券未使用+已过期 | 失效作废 | 0张 | 无法使用 |
| 整单退款+优惠券已使用 | 不退回 | 0张 | 已核销 |

**示例**：
- 用户有3张券，已使用2张，整单退款1张未使用的未过期券 → 退回1张，可用变为2张
- 用户有3张券，已使用2张，整单退款1张已过期的 → 不退回，可用仍为1张

#### 8.3.2 部分退款场景

| 场景 | 优惠券状态 | 说明 |
|------|-----------|------|
| 部分退款（任何情况） | 继续使用，不退回 | 优惠已分摊到各商品，不追溯 |

**核心原则**：
1. 部分退款不退优惠券（无论是否过期）
2. 剩余商品继续使用原优惠券
3. 部分退款后，即使剩余金额低于门槛，优惠券仍然有效（订单已使用，不可更换）

**示例**：
- 原订单：商品A ¥600 + 商品B ¥400 = ¥1000，使用满500减50
- 部分退款：退款商品A（实退¥570，含分摊优惠¥30）
- 剩余：商品B ¥400，优惠券继续可用（不可更换）

## 十一、优惠券状态显示逻辑

### 11.1 判断优先级

```
Step 1: 判断客户范围 → 不符合则不显示（用户看不到）
Step 2: 判断商品范围 → 不符合则不显示（用户看不到）
Step 3: 判断库存/有效期 → 不符合则不显示
Step 4: 判断是否已领取 → 已领取则显示"去使用"
Step 5: 全部符合 → 显示"立即领取"
```

> **"已过期"判定机制（2026-08-08补充）**：全文所有"是否已过期"的判断，统一为**实时比对**（`当前时间 > valid_until` 即视为已过期），不依赖定时任务批量刷新状态。这样确保领取展示、自动选券、退款处理这几处判断逻辑始终一致，不会出现"卡在有效期最后一刻"因为定时任务还没跑到而判断不一致的情况。

### 11.2 商品详情页

针对当前商品的可用券

| 券状态 | 是否显示 | 按钮/说明 |
|--------|----------|------------|
| 已领取 | ✅ 显示 | [去使用] |
| 未领取 + 有库存 + 未过期 | ✅ 显示 | [立即领取] |
| 未领取 + 已过期 | ❌ 不显示 | - |
| 未领取 + 没库存 | ❌ 不显示 | - |

### 12.3 确认订单优惠明细（v1.4新增）

**页面布局规范**：

| 区块 | 内容 |
|------|------|
| 商品清单 | 商品图+名称+规格+单价（展示金额） |
| 优惠明细 | 优惠券（-¥50）+ 积分抵扣（-¥10） |
| 运费信息 | 运费¥0（已满99免运费） |
| 优惠分摊明细（可展开） | 优惠券按金额占比分摊 + 积分抵扣分摊 |
| **实付金额（到手价）** | **高亮显示¥740.00** |
| 换券入口 | 已选券旁边显示"换券 ›"链接 |

**到手价计算公式**：
```
实付金额（到手价）= 商品金额 - 优惠券优惠 - 积分抵扣 + 运费
                 = ¥800.00 - ¥50.00 - ¥10.00 + ¥0.00
                 = ¥740.00
```

**优惠分摊明细**（按金额占比）：
```
优惠券（满500减50）：
  - 模具钢 H13 ×2 → -¥37.50（占比75%）
  - 模具钢 DC53 ×1 → -¥12.50（占比25%，尾差吸收项）

积分抵扣（100积分抵¥10）：
  - 按订单金额占比分摊
```

> **2026-08-17说明（方案B处理）**：本节示例是"确认订单页含积分抵扣"的展示场景，用的商品是**模具钢 H13 + 模具钢 DC53**（总金额¥800，含¥10积分抵扣），跟§12.8"场景C"的示例（刀入子×5 + 精密导柱×1，总金额¥1987，纯优惠券无积分）是**两笔不同的独立示例订单**。此前本节误用了跟§12.8相同的"刀入子/精密导柱"商品名、且数量不同（×2 vs ×1），容易让人误以为同一笔订单数字对不上，已换成不同商品名彻底区分。分摊算法统一以§12.8定义的公式为准（该商品金额÷订单商品总金额×总优惠，最后一件尾差吸收）。

**优惠券门槛计算口径（v1.4明确）**：
- 门槛按商品**展示金额**（折扣价或原价）计算
- 折扣价商品能正常使用优惠券（不禁用）
- 示例：商品折扣价¥800，满500减50可用 → ¥800 ≥ ¥500 ✅

**交互规范**：
- 点击"换券" → 打开优惠券选择弹窗
- 积分抵扣：默认勾选，用户可关闭
- 分摊明细：默认收起，点击"查看详情"展开

**原型文件**：`v2.0-PC-确认订单优惠券.html`（PC端）、`v2.0-WX-10确认订单优惠券.html`（小程序）

### 12.4 多商品选券逻辑（v1.5新增）

**自动选券规则**：
1. **优惠金额最大优先**：进入确认订单页时，自动选择优惠金额最大的可用券
2. **金额相同 → 快过期优先**：相同优惠金额时，选择到期时间更快的券
3. **仍相同 → 领取时间早的优先**：优惠金额和到期时间都相同时，按用户领取这张券的时间更早的优先（2026-08-08补充第三级排序，避免两张配置完全一样的券选谁没定义）
4. **含限时折扣商品 → 不自动选券**：提示"购物车包含限时折扣商品，不可使用优惠券"
5. **没有可用券 → 优惠券区域显示"暂无可用优惠券"占位提示**（2026-08-08补充，之前只讲了有券时怎么选，没讲没券时界面该长什么样）

**手动切换**：
- 用户可手动切换到其他可用券
- 切换后重新计算优惠分摊明细
- 手动切换后不再自动选最优（以用户选择为准）

**示例**：
- 购物车商品：商品A ¥600 + 商品B ¥400 = ¥1000
- 可用券：满500减50（省¥50）、满300减30（省¥30）
- 自动选中：满500减50
- 用户手动切换：可切换为满300减30

> 🔵 **待PM确认（2026-08-08）**：以上规则只覆盖了"进入页面时自动选一次"和"用户主动手动切换"两种情况。用户在页面停留期间加/减购物车商品、改数量（没有手动换券）时，原来选中的券可能因为金额变化跌破门槛、或者本来次优的券变成了最优，**要不要重新触发一次自动选券？** 需要你明确规则，否则容易出现"用了一张实际已经不满足条件的券"或者"该换更优惠的券但没换"的情况。

| 优惠券 | 满500减50 |

**分摊明细**（按各商品金额占比）：

> **分摊算法（2026-08-08补充，之前没写清楚）**：每个商品的分摊优惠 = 该商品金额 ÷ 订单商品总金额 × 总优惠，精确计算后四舍五入到分；最后一件商品的分摊金额 = 总优惠 - 前面所有商品分摊金额之和（用来吸收尾差，确保加总正好等于总优惠，不会出现因为逐项四舍五入导致差1分钱对不上账的情况）。**不要先把占比四舍五入到百分比再乘总优惠**，那样商品数量多的时候容易出现分摊总和对不上总优惠的情况。

| 商品 | 金额 | 占比 | 分摊优惠 | 实付 |
|------|------|------|---------|------|
| 刀入子×5 | ¥407 | 20.48% | -¥10.24 | ¥396.76 |
| 精密导柱×1 | ¥1580 | 79.52% | -¥39.76（尾差吸收项） | ¥1540.24 |

**场景D：多商品折扣券（含分摊明细）**
| 字段 | 值 |

| 商品A | 模具钢 H13 ¥300×2 = ¥600.00 |
| 商品B | 模具钢 DC53 ¥200×1 = ¥200.00 |
| 订单商品总金额 | ¥800.00 |
| 优惠券 | 满300享8折（优惠¥160） |
| 折扣率 | 0.8 |

**分摊明细**：
| 商品 | 金额 | 占比 | 分摊优惠 | 实付 |
|------|------|------|---------|------|
| H13×2 | ¥600 | 75% | -¥120 | ¥480 |
| DC53×1 | ¥200 | 25% | -¥40 | ¥160 |

### 12.9 退款场景

#### 12.9.1 整单退款 - 未过期退券
| 字段 | 值 |
|------|------|
| 场景 | 整单退款，优惠券未过期 |
| 处理 | ✅ 优惠券退回账户（有效期不变），恢复可用状态 |
| 示例 | 用户订单用满500减50，退款后券退回，有效期至2026-06-30 |

#### 12.9.2 整单退款 - 已过期不退券
| 字段 | 值 |
|------|------|
| 场景 | 整单退款，优惠券已过期 |
| 处理 | ❌ 优惠券失效作废，不退回 |
| 示例 | 用户订单用满300减30（有效期至2026-05-31），退款时不予退回 |

#### 12.9.3 部分退款（部分商品退款）
| 字段 | 值 |
|------|------|
| 核心原则 | 退款商品分摊的优惠金额不追溯退还 |
| 剩余优惠券 | 继续使用原优惠券，优惠保持不变 |
| 注意事项 | 部分退款后，即使剩余金额低于门槛，优惠券仍然有效（订单已使用，不可更换） |

**示例**：
| 字段 | 值 |
|------|------|
| 原订单 | 商品A ¥600 + 商品B ¥400 = ¥1000 |
| 优惠券 | 满500减50（分摊给A ¥30，B ¥20） |
| 部分退款 | 退款商品A →退款 ¥570（¥600-¥30分摊） |
| 剩余商品 | 商品B ¥400，优惠券不追溯退还，继续可用 |

### 12.10 购物车自动选券规则

进入购物车时，自动计算并选中最优惠的一张可用券，**规则与§12.4完全相同**（同一套选券算法，购物车和确认订单页是两个触发入口，不是两套独立逻辑）：
1. 优惠金额最大优先
2. 金额相同 → 快过期优先
3. 含限时折扣商品 → 不自动选券，提示"⚠ 购物车包含限时折扣商品，不可使用优惠券"

> **2026-08-08 说明**：此前§12.4和§12.10各写了一遍完整规则文字，内容重复，容易被误解成两套独立逻辑，现已合并为"规则相同、两个入口各自触发一次"，与§12.4互相引用。

**上下架规则**（2026-08-08补充，之前只在列表页出现两次没有专门说明，参照§十删除规则的逻辑处理）：
- 下架后：领券中心、商品详情页立即不再展示（新用户看不到、不能再领）
- 已领取未使用的券：不受影响，继续可用，直到过期或使用（跟"删除"保持一致的处理方式）
- 自动发放规则（如新用户注册自动发）命中一张已下架的券：跳过，不发放
- 重新上架：立即恢复展示，可以正常领取
