## 1. 模块定位

### 1.1 解决什么

对应需求分析 P1–P4：平台缺少营销杠杆（P1）、运营无法自主配置活动（P2）、新客首单转化难（P3）、客单价偏低（P4）。

本模块提供覆盖 **小程序端 / PC 端 / 商家后台** 的完整优惠券能力：券的创建与发放、领取与核销、退款退券、状态展示与商家管理。

### 1.2 依赖谁（上游）

| 依赖模块 | 依赖内容 | 说明 |
|---|---|---|
| 用户与认证体系 | 用户身份（未认证 / 个人认证 / 企业认证）、新老客判定（是否完成首单） | 决定「客户范围」能否生效 |
| 商品与类目 | 商品 ID、类目 ID、商品展示金额 | 决定「商品范围」与「门槛判定」 |
| 购物车 | 商品件数、数量、金额 | 决定选券与分摊计算 |
| 订单 | 订单金额、订单状态 | 券核销与退款退券的触发方 |
| 支付与退款 | 实付金额口径 | 决定整单退款金额 |
| 积分体系 | 积分余额、抵扣比例、是否可叠加 | 本模块不做积分体系，仅做叠加开关与 UI |
| 限时折扣活动 | 商品是否处于限时折扣 | 本模块不做活动配置，仅做互斥判定 |

> 🔵 **待确认**：以上依赖模块的正式系统名与对接方（接口 owner）【待确认】。

### 1.3 被谁依赖（下游）

| 使用方 | 用途 |
|---|---|
| 运营 | 配置发券活动、查看领取与核销 |
| 订单模块 | 下单时校验与核销券 |
| 退款模块 | 退款时判定券是否退回 |
| 财务 | 券优惠金额的对账口径 |
| 数据/BI | 领用率、核销率统计（F16，第三期） |

### 1.4 不包含什么（边界）

- **不含积分体系本身**：积分的获取、消耗、抵扣比例由积分模块定义（F17）
- **不含限时折扣活动的配置能力**（F18）
- **不含短信 / 小程序推送通知**：退款退券仅做站内折叠提示（F19）
- **不含阶梯满减券**（第二期，F14）
- **不含批量兑换码与数据统计**（第三期，F15/F16）

### 2.3 客户范围（券配置维度，非角色）

券可配置的领取对象：全部用户 / 已认证用户 / 已认证个人用户 / 已认证企业用户 / 未认证用户 / 新用户 / 老用户 / 指定客户（下拉勾选或 Excel 导入）。

**新用户定义**：注册后未完成首单的客户（含已注册但未下单）。
**老用户定义**：有完成订单记录的客户。

## 2.5 用户场景

> 撮合系统标准要求：用户场景**不是**「谁 / 页面 / 能力」的表格，而是**一个故事**。
> ⚠️ 以下三个场景是基于现有业务规则建构的**典型场景**，客户身份细节（行业、年龄、规模）**属于推断，需业主按真实客户修正**。

### 场景一：新客首单（对应 F4 自动发放 + F1 满减券）

> 【谁】{【待确认】请按真实客户画像修正：行业 / 规模 / 角色}
> 【什么情况】客户经同行介绍第一次来平台，注册后不知道该买什么、担心单价高
> 【遇到什么】看到首页有"新客立减"的券包，但不确定能不能用、怎么用
> 【要什么】注册即得券，且券在商品页、购物车、下单页都能清楚看到"用这张券能省多少"
> 【用完去哪】首单用掉券，下次回来还想看有没有新券 → 领券中心

**由此推导的刚需（不是加分项）**：
- 自动发放必须在注册成功时即时到账（不能等定时任务）
- 券的"省多少"必须前置展示到商品列表与详情页（对应 §4.8 券后价规范）
- 券门槛必须让客户看懂（对应「不满足门槛」标签）

### 场景二：老客下单用券（对应 F10 选券 + F7 分摊）

> 【谁】{【待确认】} 一位有多次采购记录的客户
> 【什么情况】采购 2 种物料（单价差异大），金额 ¥1987，手里有 3 张券
> 【遇到什么】不知道哪张最划算；上次担心"退了一件商品券会不会失效"而不敢用券
> 【要什么】系统自动选最优券，自己还能换；退款时规则要说清楚
> 【用完去哪】下单 → 收到货 → 部分退款 → 看到券的明确状态说明

**由此推导的刚需**：
- 自动选券要按「优惠金额最大 → 快过期 → 领取时间早」三级排序（对应 §4.9）
- 部分退款不退券必须对用户明说（对应 §4.9.8 折叠提示）

### 场景三：商家运营发券（对应 F11 商家端）

> 【谁】{【待确认】} 平台运营人员
> 【什么情况】要上一档"满 500 减 50"的新客券，预算有限需控制发行量
> 【遇到什么】以前提需求等开发发版，一周后才能上；发行量中途想加又得提需求
> 【要什么】自己建券、自己调发行量、自己上下架，改完立刻生效
> 【用完去哪】看领取与核销数据，决定要不要追加

**由此推导的刚需**：
- 配置即生效，无发版依赖（对应 G3）
- 发行量支持增量修改，且不得小于已发放数（对应 §4.10）
- 上下架与删除不能影响已领用户权益（对应 §4.7）

## 3. 业务对象与状态机

### 3.1 业务对象

| 对象 | 说明 |
|---|---|
| 优惠券（coupon） | 券模板：类型、门槛、优惠内容、适用范围、发行量、有效期、上架状态 |
| 用户券（user_coupon） | 用户领取到的券实例：状态、领取时间、**领取时的配置快照** |
| 兑换码（coupon_code） | 第三期：一券一码，码与券多对一 |
| 订单券关联（order_coupon） | 订单使用的券、分摊明细、核销时间 |

> ⚠️ **user_coupon 与 order_coupon 为 v2.0 新增定义**（原 PRD 的数据结构章节未包含，导致 §4.7 的编辑承诺无载体）。详见 §6。

### 3.2 券模板状态（coupon）

| 当前状态 | 触发事件 | 目标状态 | 对用户的影响 |
|---|---|---|---|
| 上架 | 商家下架 | 下架 | 领券中心/商品详情页不再展示；已领取未使用的券不受影响 |
| 下架 | 商家上架 | 上架 | 立即恢复展示、可领取 |
| 上架/下架 | 有效期结束（实时判定） | 已过期 | 未领取的不再展示；已领取未使用的判定为已过期 |
| 上架/下架 | 商家删除 | 已删除 | 未领取的不展示；已领取未使用的**继续可用至过期**（见 §4.7） |

### 3.3 用户券状态（user_coupon）

```
未领取 ──领取──→ 未使用 ──下单核销──→ 已使用
                    │
                    └──有效期结束（实时判定）──→ 已过期
```

| 当前状态 | 触发事件 | 目标状态 | 备注 |
|---|---|---|---|
| 未使用 | 用户下单并使用该券 | 已使用 | 不可逆（不退回，见 §4.6） |
| 未使用 | 当前时间 > 有效期截止 | 已过期 | **实时比对**，不依赖定时任务 |
| 未使用 | 整单退款 + 未过期 | 未使用（退回账户） | 有效期不变 |
| 未使用 | 整单退款 + 已过期 | 已过期 | 不退回 |
| 已使用 | 整单退款 | 已使用（不退回） | — |
| 已使用/未使用 | 部分退款 | 不变 | 部分退款不退券 |

**统一口径**：全文「已失效」与「已过期」为**同一个状态**，统一使用「已过期」（删除券不产生额外的失效状态）。

### 3.4 兑换码状态（coupon_code，第三期）

| 状态 | 说明 |
|---|---|
| 未兑换 | 码已生成未使用 |
| 已兑换 | 已被使用，券已发放到用户账户 |
| 已过期 | 超过券有效期 |

## 4. 功能需求

> 每项功能按「规则 / 数据 / 异常 / 验证点」四要素描述。**本次新增的异常与验证点**均标注来源；无法确定的标【待确认】。

### 4.1 优惠券类型

#### 4.1.1 满减券（单档） — F1（Must）

| 字段 | 说明 | 校验 |
|------|------|------|
| 类型 | FULL_REDUCTION | — |
| 门槛金额 | 满 X 元 | X > 0 |
| 优惠金额 | 减 Y 元 | Y > 0，且 门槛金额 − Y ≥ 0.1 |

> **校验口径（2026-08-08 修正）**：校验对象是**门槛金额**，不是订单金额——创建券时不存在具体订单，需确保按最低门槛下单时实付不趋近于 0。
> **异常/验证点**：门槛金额 ≤ 0 → 拒绝创建；优惠金额 ≥ 门槛金额 → 拒绝创建（提示示例文案【待确认】）。

#### 4.1.2 折扣券（单档） — F2（Must）

| 字段 | 说明 | 校验 |
|------|------|------|
| 类型 | DISCOUNT | — |
| 门槛金额 | 满 X 元 | X > 0 |
| 折扣率 | 打 Y 折 | 1 ≤ Y ≤ 9.9 |
| 实付金额 | 门槛金额 × Y 折 | ≥ 0.1 |

> **校验口径（2026-08-08 修正）**：按最低门槛金额计算，避免「门槛设太低 + 折扣太狠」导致实付趋近 0。

#### 4.1.3 阶梯满减券 — F14（Should，第二期）

本期不做，数据结构预留（见 §6、§11）。

### 4.2 适用范围

#### 4.2.1 上架平台

| 选项 | 说明 | 库存 |
|------|------|------|
| PC 端 | 仅 PC 端可用 | 独立 |
| 小程序端 | 仅小程序端可用 | 独立 |
| 全部 | PC 端 + 小程序端可用 | 共享 |

#### 4.2.2 商品范围

| 选项 | 说明 |
|------|------|
| 全部商品 | 商城任意商品 |
| 指定分类 | 指定分类商品（多选） |
| 指定商品 | 指定 SKU 商品（多选） |

#### 4.2.3 客户范围

见 §2.3。**已认证用户**包含已认证个人用户与已认证企业用户；**未认证用户**是否可领由券配置决定。

> **异常/验证点**：客户范围与商品范围同时限制时，需**同时满足**才可领可用（逻辑与，非或）。
> 🔵 **待确认**：券配置中「未认证用户」默认是否勾选【待确认】。

### 4.3 发放方式

#### 4.3.1 三种方式（可并存）

| 方式 | 说明 |
|------|------|
| 手动领取 | 客户在领券中心主动领取 |
| 自动发放 | 新用户注册成功时发放 |
| 兑换码 | 发行量生成对应数量兑换码（第三期，F15） |

#### 4.3.2 自动发放触发条件

| 触发条件 | 说明 |
|----------|------|
| 新用户注册（全部） | 所有新注册用户（个人 + 企业） |
| 新用户注册（仅个人） | 仅个人新用户（已实名） |
| 新用户注册（仅企业） | 仅企业新用户（已认证） |
| 指定客户立即发放 | 勾选指定客户后立即发放 |

**存量用户处理（2026-08-08 补充默认规则）**：规则上线时**不回溯补发**给规则生效前已符合条件的老用户，仅对规则生效后新发生的「注册」事件生效；如需对存量补发，走「指定客户立即发放」手动配置。

> **异常（v2.0 新增）**：自动发放命中一张**已下架**的券 → 跳过发放（与 §4.7 一致）。
> 🔵 **待确认**：自动发放时用户**已通过领券中心领过同一张券**（触发限领约束）→ 跳过发放还是发放失败记录日志？【待确认】
> **验证点**：注册事件重复投递（如消息重试）不得重复发券（幂等，见 §9）。

#### 4.3.3 兑换码（第三期，F15）

| 字段 | 说明 |
|------|------|
| 格式 | 8–16 位字母数字组合，存储时转大写 |
| 生成数量 | = 发行量 |
| 有效期 | 与优惠券有效期一致 |

#### 4.3.4 发放冲突控制

**核心原则**：每人每张券限领 N 张（默认 1 张）。

```
领取前去重检查：user_id + coupon_id 唯一
```

> **异常（v2.0 新增）**：并发领取同一张券的最后 1 个库存 → 需保证不超发（实现约束见 §9）。
> **异常（v2.0 新增）**：库存不足时前端表现【待确认：是置灰按钮还是领取后提示】。

### 4.4 限制规则

| 规则 | 默认值 | 说明 |
|------|--------|------|
| 每人限领 | 1 张 | 跨平台共享（PC 端与小程序端同一用户不可重复领） |
| 每单限用 | 1 张 | 不可叠加 |
| 发行量范围 | 1 ~ 999999 | — |
| 积分叠加 | 见 §4.4.1 | 可配置支持/不支持 |

#### 4.4.1 积分叠加

| 选项 | 说明 |
|------|------|
| 支持 | 可同时使用优惠券 + 积分抵现 |
| 不支持 | 不可同时使用 |

> **UI 对应规则（2026-08-08 补充默认规则）**：确认订单页积分抵扣勾选框，当所选券为「不支持」时**置灰不可点**并提示「当前优惠券不支持积分叠加」；用户换券后若新券支持叠加，勾选框恢复可用并重置为默认勾选。
> **验证点**：券不支持叠加时，即使积分开关被置灰，提交订单请求也不得同时携带券与积分（后端兜底校验）。

### 4.5 促销叠加逻辑

#### 4.5.1 计算优先级

```
Step 1: 限时折扣 → 商品折扣价
Step 2: 优惠券 → 判断是否可用
Step 3: 积分抵现 → 根据券设置判断
```

#### 4.5.2 限时折扣商品不可用优惠券

**规则**：购物车中任何商品为限时折扣 → **整单不可用优惠券**。

> ⚠️ **概念澄清（v2.0 新增，原 PRD 未定义，开发易混淆）**：
> - **限时折扣**：平台促销**活动**，有时间区间与活动价格，与券**互斥**
> - **折扣价**：商品本身的**定价**（如原价 ¥1000、折扣价 ¥800），**不互斥**，可作为门槛计算基数
> **本模块只判定第一种**（是否处于限时折扣活动）；判定数据由活动模块提供。

#### 4.5.3 提示文案

| 时机 | 文案 |
|------|------|
| 下单页勾选优惠券时 | 「购物车包含限时折扣商品，该订单不可使用优惠券」 |
| 提交订单时（兜底） | 「您的订单包含限时折扣商品，无法使用优惠券，如需使用优惠券，请将限时折扣商品移出购物车」 |
| 商品详情页领券时 | 「限时折扣商品不可用此券」（备注说明） |
| **购物车页（v2.0 补充，对应 §4.9 自动选券）** | 「⚠ 购物车包含限时折扣商品，不可使用优惠券」 |

### 4.6 退款退券规则

#### 4.6.1 基础规则

| 场景 | 处理 |
|------|------|
| 券已使用 | ❌ 不退回 |
| 券未使用 + 未过期 | ✅ 退回至客户账户，可继续使用（有效期不变） |
| 券未使用 + 已过期 | ❌ 失效作废，不可再用 |

#### 4.6.2 多商品优惠分摊原则（F7，Must）

```
商品A分摊优惠 = 优惠券总优惠 × (商品A金额 / 订单商品总金额)
```

**满减券示例**：满 500 减 50；商品 A ¥600、商品 B ¥400，合计 ¥1000

| 商品 | 金额 | 占比 | 分摊优惠 | 实付金额 |
|------|------|------|---------|---------|
| 商品 A | ¥600 | 60% | −¥30 | ¥570 |
| 商品 B | ¥400 | 40% | −¥20 | ¥380 |
| **合计** | ¥1000 | 100% | **−¥50** | **¥950** |

**折扣券示例**：满 300 享 8 折；商品 A ¥600、商品 B ¥400，合计 ¥1000，折扣率 0.8，优惠金额 ¥200

| 商品 | 金额 | 占比 | 分摊优惠 | 实付金额 |
|------|------|------|---------|---------|
| 商品 A | ¥600 | 60% | −¥120 | ¥480 |
| 商品 B | ¥400 | 40% | −¥80 | ¥320 |
| **合计** | ¥1000 | 100% | **−¥200** | **¥800** |

#### 4.6.3 分摊算法（2026-08-08 补充）

> 每件商品的分摊优惠 = 该商品金额 ÷ 订单商品总金额 × 总优惠，**精确计算后四舍五入到分**；**最后一件商品的分摊金额 = 总优惠 − 前面所有商品分摊金额之和**（吸收尾差），确保加总恰好等于总优惠。
> **禁止**先把占比四舍五入到百分比再乘总优惠（商品多时会分摊总和对不上）。

**示例（尾差吸收）**：刀入子 ¥407 + 精密导柱 ¥1580 = ¥1987，满 500 减 50

| 商品 | 金额 | 占比 | 分摊优惠 | 实付 |
|------|------|------|---------|------|
| 刀入子 ×5 | ¥407 | 20.48% | −¥10.24 | ¥396.76 |
| 精密导柱 ×1 | ¥1580 | 79.52% | −¥39.76（尾差吸收项） | ¥1540.24 |

#### 4.6.4 部分退款规则（F8，Must）

1. 按退款商品金额占比计算应退金额（含优惠分摊部分）
2. **已优惠部分不追溯退还**
3. 剩余商品继续使用原优惠券，优惠保持不变
4. 部分退款后**即使剩余金额低于门槛**，券仍然有效（订单已使用，不可更换）
5. **部分退款不退券**（无论是否过期）

#### 4.6.5 整单退款金额口径（v2.0 决策确认）

> ✅ **决策（2026-10-06 业主确认）**：整单退款退**订单实付金额**（非商品原价、非商品金额合计）。
> 例：商品合计 ¥1000、用券 −¥50、实付 ¥950 → 整单退款退 **¥950**；券本身按 §4.6.1 规则判定是否退回。

#### 4.6.6 退款券状态变化总表

| 场景 | 券状态 | 退回可用数量 | 说明 |
|------|-----------|-------------|------|
| 整单退款 + 未使用 + 未过期 | 退回账户 | 1 张 | 有效期不变 |
| 整单退款 + 未使用 + 已过期 | 失效作废 | 0 张 | 无法使用 |
| 整单退款 + 已使用 | 不退回 | 0 张 | 已核销 |
| 部分退款（任何情况） | 继续使用，不退回 | 0 张 | 优惠已分摊到各商品，不追溯 |

> **异常/边界（v2.0 新增）**：退回时券**临近过期**（如剩余不足 1 小时）→ 【待确认：是否提示用户；建议退回时在提示中标注剩余有效期，不做延长】。

#### 4.7.3 上下架规则（2026-08-08 补充）

#### 4.9.3 自动选券规则

1. **优惠金额最大优先**
2. **金额相同 → 快过期优先**（到期时间更早）
3. **仍相同 → 领取时间早的优先**（2026-08-08 补充第三级排序）
4. **含限时折扣商品 → 不自动选券**，提示见 §4.5.3
5. **无可用券 → 显示「暂无可用优惠券」占位提示**（2026-08-08 补充）

> ✅ **决策（2026-10-06 业主确认）：页面停留期间购物车变化 → 重新计算选券，但不覆盖用户的手动选择。**
> 具体规则：
> - 用户**未手动换过券**时，加/减商品、改数量后**重新触发一次自动选券**（按上述三级排序）
> - 用户**已手动换过券**后，不再自动覆盖；但**必须在提交订单前做一次校验**——若该券已不满足条件（金额跌破门槛/商品范围不符/出现限时折扣商品），拦截提交并提示用户重新选券
> - 提示文案【待确认】

- 用户可手动切换到其他可用券
- 切换后重新计算优惠分摊明细
- 手动切换后不再自动选最优（以用户选择为准）

#### 4.9.5 确认订单优惠明细

| 区块 | 内容 |
|------|------|
| 商品清单 | 商品图 + 名称 + 规格 + 单价（展示金额） |
| 优惠明细 | 优惠券（−¥50）+ 积分抵扣（−¥10） |
| 运费信息 | 运费 ¥0（已满 99 免运费） |
| 优惠分摊明细（可展开） | 券按金额占比分摊 + 积分抵扣分摊 |
| **实付金额（到手价）** | **高亮显示 ¥740.00** |
| 换券入口 | 已选券旁显示「换券 ›」 |

**到手价计算**：
```
实付金额（到手价）= 商品金额 − 优惠券优惠 − 积分抵扣 + 运费
                 = ¥800.00 − ¥50.00 − ¥10.00 + ¥0.00 = ¥740.00
```

**优惠分摊明细示例**（与 §4.6.3 算法一致）：
```
优惠券（满500减50）：
  - 模具钢 H13 ×2 → −¥37.50（占比75%）
  - 模具钢 DC53 ×1 → −¥12.50（占比25%，尾差吸收项）
积分抵扣（100积分抵¥10）：按订单金额占比分摊
```

> **示例说明（2026-08-17）**：本节示例（H13 + DC53，¥800，含积分）与 §4.9.7 场景 C（刀入子 + 精密导柱，¥1987，纯券）是**两笔独立示例订单**，数字不可交叉比对。

**交互**：点「换券」→ 打开选券弹窗；积分抵扣默认勾选、可关闭；分摊明细默认收起、点击展开。

## 5. 主流程与异常路径（v2.0 新增）

### 5.1 领券主流程

```
入口①  领券中心 → 选中券 → 点击「立即领取」
          ├ 校验：库存 > 0 ？
          ├ 校验：未过期（实时比对）？
          ├ 校验：限领未用尽（user_id + coupon_id 唯一）？
          ├ 校验：符合客户范围 / 商品范围？
          └ 全部通过 → 扣减库存 → 生成 user_coupon（写入配置快照）→ Toast「领取成功」→ 按钮变「去使用」

入口②  新用户注册成功 → 命中自动发放规则 → 同入口①的校验流程（跳过客户范围中的「新用户」判定）
入口③  兑换码兑换（第三期）→ 校验码状态与有效期 → 发券
```

**异常路径**

| 异常 | 处理 |
|---|---|
| 库存为 0（并发抢最后 1 张） | 领取失败提示「券已抢光」【文案待确认】 |
| 券已过期 | 领取入口不展示该券（前端已过滤）；接口侧需兜底拒绝 |
| 已达限领上限 | 按钮显示「去使用」；接口侧拒绝重复领取 |
| 不符合客户范围 | 前端不展示；接口侧拒绝（防绕过） |
| 网络失败 / 超时 | 【待确认：是否提供重试入口】 |
| 重复提交（连点两次） | 幂等：同 user + 同 coupon 只生成一条 user_coupon（唯一索引保证） |

### 5.2 用券主流程

```
商品详情页看券 → 加购 → 购物车（自动选最优券）→ 确认订单页（选券/换券/积分抵扣）
   → 提交订单
      ├ 校验：券未过期、未使用、符合范围、金额 ≥ 门槛、无限时折扣商品
      ├ 校验：所选券与积分是否可叠加
      └ 通过 → 核销券（状态 → 已使用）→ 写 order_coupon（含分摊明细）→ 生成订单
```

**异常路径**

| 异常 | 处理 |
|---|---|
| 提交时券刚好过期 | 拦截提交，提示重新选券【文案待确认】 |
| 提交时券被其他订单占用 | 拦截，提示券不可用 |
| 购物车变化导致跌破门槛 | 见 §4.9.3 决策：用户未手动选过 → 重算；已手动选过 → 提交前校验拦截 |
| 出现限时折扣商品 | 整单不可用券，提示见 §4.5.3 |
| 提交订单接口超时后用户重试 | 幂等：以订单号去重，禁止同一订单重复核销 |

### 5.3 退款退券主流程

```
退款申请 → 退款成功
   ├ 整单退款 → 判定券状态
   │     ├ 未使用 + 未过期 → 退回账户（有效期不变）
   │     ├ 未使用 + 已过期 → 作废
   │     └ 已使用 → 不退回
   └ 部分退款 → 券不退，剩余商品继续用原券
   退款金额 = 订单实付金额（见 §4.6.5）
   前端：订单详情页折叠式提示（见 §4.9.8）
```

**异常路径**

| 异常 | 处理 |
|---|---|
| 退款成功但券退回失败 | 【待确认：补偿机制（重试/人工）】 |
| 同一订单多次退款 | 券只按最终状态判定一次，不可重复退回 |

## 9. 非功能与约束（v2.0 新增）

| 类别 | 要求 | 说明 |
|---|---|---|
| **并发防超发** | 券库存扣减必须原子操作；`UNIQUE(user_id, coupon_id)` 兜底防重复领取 | 对应 §4.3.4；限领 1 张 + 发行量上限下，并发抢最后 1 张不得超发 |
| **幂等** | 领取、核销、退回三个写入接口必须幂等 | 网络重试/用户连点不得产生重复数据 |
| **金额精度** | 内部按「分」计算；分摊先精确计算再四舍五入到分；最后一项吸收尾差 | 对应 §4.6.3 |
| **金额显示** | 展示 2 位小数；券后价不得为负数 | 对应 §4.8.9 |
| **状态一致性** | 过期判定统一实时比对，禁止依赖定时任务 | 对应 §4.8.1 |
| **数据隔离** | 商家后台数据按商家隔离（跨商家不可见） | 【待确认】平台是否已有租户隔离机制 |
| **审计** | 券的新增/编辑/复制/上下架/删除/发行量变更全部记操作日志 | 对应 §4.10.3 |
| **性能** | 券列表查询响应时间【待确认】；领取接口 QPS【待确认】 | 无基线数据，待补充 |
| **兼容性** | 小程序端与 PC 端同一套规则、同一套算法 | 对应 §4.9.9 |

| 1 | 用已认证个人账号登录小程序 → 进「领券中心」 | 默认停在「可领取」Tab；券按快过期优先排序 |

| 8 | 商家后台 → 优惠券列表 → 新增满 500 减 50 | 保存成功；列表出现新券，状态为上架 |

| 1 | 商家后台新增券：门槛填 0 / 优惠金额 ≥ 门槛 | 提交按钮应为灰（或提交被拒并给出原因） |

| 4 | 购物车金额低于券门槛 | 该券不出现在可用列表；商品列表页显示「不满足门槛」灰标签 |
