## 三、主流程（端到端闭环）

```
【领券侧】
新用户注册 ──→ 系统自动发券（命中规则）──→ 券入账户
游客/用户 ──→ 领券中心 ──→ 立即领取 ──→ 券入账户（受限领约束）
                              ↓ 不符合条件
                          不展示（用户无感知）

【用券侧】
商品详情页（看到可用券）─→ 加购 ──→ 购物车（自动选最优券）
    ──→ 确认订单页（选券/换券/积分抵扣）──→ 提交订单 ──→ 券核销（已使用）

【退款侧】
订单退款 ──┬─ 整单退款 + 券未使用 + 未过期 ──→ 券退回账户（有效期不变）
           ├─ 整单退款 + 券未使用 + 已过期 ──→ 券作废，不退回
           ├─ 整单退款 + 券已使用 ─────────→ 券不退回
           └─ 部分退款（任何情况）────────→ 券不退，剩余商品继续用
```

## 四、功能清单与优先级（F）

> 定级标准：**Must**=缺了主流程走不通或直接服务量化目标；**Should**=提升效率体验但不阻断；**Could**=依赖未确认条件；**Won't**=本期明确不做（必写理由）

| 编号 | 功能 | 级别 | 对应痛点/目标 | 说明 |
|---|---|---|---|---|
| F1 | 满减券（单档） | **Must** | P1/P3、G1/G2 | 一期核心 |
| F2 | 折扣券（单档） | **Must** | P1/P3、G1/G2 | 一期核心 |
| F3 | 手动领取（领券中心） | **Must** | P1、G1 | 主获客入口 |
| F4 | 自动发放（新客注册触发） | **Must** | P3、G1 | 新客转化关键 |
| F5 | 适用范围（平台/商品/客户） | **Must** | P1 | 无范围控制 = 券不可用 |
| F6 | 限领与每单限用规则 | **Must** | P1 | 资金安全底线 |
| F7 | 多商品优惠分摊 + 尾差吸收 | **Must** | P1 | 资金安全底线 |
| F8 | 退款退券规则（含部分退款） | **Must** | P1 | 资金安全底线 |
| F9 | 券状态显示逻辑（三端） | **Must** | P3 | 影响领取与用券转化 |
| F10 | 确认订单页选券（自动选最优 + 手动换） | **Must** | G2 | 决定实际优惠体验 |
| F11 | 商家端券管理（增删改查/复制/上下架/发行量/日志） | **Must** | P2、G3 | 运营自主的载体 |
| F12 | 优惠券可用商品列表页（去使用） | **Should** | G2 | 提升用券转化，不阻断主流程 |
| F13 | 分享功能（小程序卡片/链接/海报） | **Should** | G1 | 拉新辅助；海报能力【待确认】 |
| F14 | 阶梯满减券 | **Should** | G2 | 二期 |
| F15 | 批量兑换码 + 兑换明细 | **Could** | G1 | 三期；依赖券码生成与兑换链路 |
| F16 | 数据统计（领取/使用/核销率） | **Could** | G3 | 三期；依赖埋点口径【待确认】 |
| F17 | 积分体系改造 | **Won't** | — | 积分体系属独立模块，本期仅做「券与积分能否叠加」的开关与 UI |
| F18 | 限时折扣活动配置 | **Won't** | — | 属促销活动模块，本期仅做「限时折扣商品不可用券」的互斥判定 |
| F19 | 短信 / 小程序推送通知 | **Won't** | — | 本期用订单详情页折叠提示替代 |
